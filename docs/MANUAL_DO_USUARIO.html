Manual de Uso do Sistema 1. Visão Geral & Arquitetura

1. Visão Geral e Arquitetura

A Plataforma de Pedidos White-Label é uma solução completa para cardápio digital e recepção de pedidos, desenvolvida especificamente para permitir que qualquer estabelecimento alimentício (como lojas de cupcakes, confeitarias, lanchonetes de frango frito, hamburguerias ou pizzarias) utilize a mesma base de código com identidade visual, produtos e contatos totalmente personalizados.

1.1 O Padrão MVC (Model - View - Controller)

O sistema foi estruturado rigorosamente sob o padrão MVC do CodeIgniter 4, separando as responsabilidades de software:

Camada Diretório Responsabilidade
Model (Dados) app/Models/ Acesso e persistência no banco de dados, regras de integridade e consultas analíticas (ex: ProductModel, OrderModel, ProductClickModel).
View (Apresentação) app/Views/ Telas e componentes HTML5/CSS/JavaScript renderizados no navegador do cliente e do administrador.
Controller (Controle) app/Controllers/ Recepção de requisições HTTP, validação de regras de negócio (como checagem de horário comercial) e despacho para as Views.
💡
O Conceito White-Label: Uma única instalação pode ser reconfigurada a qualquer momento. Ao alterar o segmento de "Cupcakes" para "Frango Frito", toda a interface pública adota instantaneamente as cores da marca, o nome da loja e as regras correspondentes.

1.2 Ambientes de Banco de Dados

  • Desenvolvimento Local (SQLite): Banco em arquivo único (writable/database.db). Não requer servidor MySQL instalado localmente, garantindo velocidade máxima de inicialização e execução de testes.
  • Produção (VPS Hostinger): Totalmente compatível com MySQL e MariaDB através das migrações do Database Forge do CodeIgniter 4. A mesma estrutura de tabelas é gerada sem necessidade de alterar uma única linha de código.
Manual de Uso do Sistema 2. Wizard de Instalação Dinâmico

2. Wizard de Instalação Dinâmico (`/install`)

Ao iniciar o sistema pela primeira vez ou apontar para um banco zerado, o Filtro de Instalação Global (InstallFilter) detecta que as tabelas ou configurações não existem e redireciona automaticamente qualquer tentativa de navegação para a rota /install.

🛡️
Prevenção de Erros: O assistente de instalação possui validação instantânea em JavaScript antes de avançar cada etapa e bloqueia o botão de submissão para evitar disparos duplicados durante a execução das migrações.

2.1 As 4 Etapas do Wizard

1
Passo 1: Identidade da Loja & Regras White-Label

O administrador define o Nome da Loja (ex: Doce Encanto Cupcakes), seleciona o Segmento/Nicho (com botões de seleção rápida para Cupcakes, Frango Frito, Hambúrguer ou Pizza), informa o WhatsApp Comercial Oficial com DDD e os Horários de Funcionamento (abertura e fechamento).

2
Passo 2: Criação do Administrador Geral

Cadastro das credenciais do primeiro operador do painel: Nome Completo, E-mail de Acesso e Senha de no mínimo 6 dígitos. A senha é armazenada com criptografia de ponta a ponta (BCrypt / password_hash).

3
Passo 3: Revisão de Banco & Migrations

Checklist visual das tabelas relacionais que serão criadas pelo CodeIgniter (settings, users, categories, products, product_options, product_clicks, orders).

4
Passo 4: Execução Automática & Inicialização

Ao confirmar, o sistema dispara programaticamente $migrations->latest(), salva as configurações na tabela settings, cadastra o usuário, popula automaticamente o cardápio com itens de demonstração do nicho selecionado e efetua login direto no Painel Administrativo.

🔒
Bloqueio Pós-Instalação: Uma vez finalizada a instalação, qualquer tentativa de acessar a rota /install é sumariamente redirecionada para a página principal, protegendo o banco contra sobreposição.
Manual de Uso do Sistema 3. Guia do Consumidor (Catálogo & Checkout)

3. Guia do Consumidor (Catálogo Público)

A página inicial (/) oferece uma experiência fluida de compras, inspirada nos melhores padrões de Interação Humano-Computador (IHC) e comércio eletrônico moderno.

3.1 Status de Funcionamento em Tempo Real

No topo da página, um badge dinâmico informa a situação atual do estabelecimento:

  • Loja Aberta O cliente pode adicionar produtos à sacola e concluir o pedido normalmente.
  • Loja Fechada Se o cliente acessar fora do expediente configurado (ex: madrugada), um banner vermelho alerta sobre o horário e o botão de finalização do pedido é automaticamente desabilitado, prevenindo frustrações.

3.2 Navegação e Personalização de Itens

  1. Filtro por Categorias: O cliente pode clicar nas abas superiores para rolar suavemente até a categoria desejada.
  2. Card do Produto: Mostra a foto, título, descrição com sabor/ingredientes e preço unitário formatado em Reais (BRL).
  3. Modal de Personalização & Adicionais: Ao clicar no produto, um modal interativo permite escolher complementos (ex: Granulado Belga Extra, Caixa para Presente), ajustar a quantidade e visualizar o subtotal recalculado em tempo real.
  4. Rastreamento Transparente: Toda visualização de produto registra um clique assíncrono no servidor para alimentar o ranking de popularidade no Dashboard.

3.3 Sacola de Compras com Reversibilidade de Ações (IHC)

Ao adicionar um item, o botão flutuante "Ver Sacola" é exibido com o contador de itens e valor acumulado.

  • Controles Diretos: Na sacola, os botões + e - permitem ajustar quantidades instantaneamente.
  • Prevenção de Erros & Ação Reversível: Ao clicar na lixeira para excluir um item, o sistema exibe um aviso (Toast) com a opção "Desfazer" por 4 segundos, permitindo recuperar o item caso o clique tenha sido acidental.

3.4 Preenchimento de Entrega & Integração ViaCEP

1. O cliente digita o WhatsApp e o CEP residencial.

2. Graças à máscara em Vanilla JS, os dados são formatados automaticamente: (99) 99999-9999 e 99999-999.

3. Ao completar os 8 dígitos do CEP, a API do ViaCEP é consultada em segundo plano, preenchendo automaticamente a Rua, o Bairro e a Cidade, posicionando o cursor diretamente no campo Número.

3.5 Finalização e Geração do Pedido no WhatsApp

O cliente seleciona a forma de pagamento (PIX, Cartão ou Dinheiro — com campo condicional para cálculo de troco).

Ao clicar em "Finalizar no WhatsApp":

  1. O pedido é salvo no banco de dados relacional com um número identificador exclusivo (ex: #1).
  2. O carrinho local é esvaziado.
  3. O cliente é redirecionado para o WhatsApp oficial com a mensagem pronta e codificada:

Manual de Uso do Sistema 4. Guia do Administrador

4. Guia do Administrador (Painel `/admin`)

A área administrativa é restrita e protegida pelo filtro AuthFilter. Sem login ativo, qualquer acesso a rotas iniciadas com /admin é bloqueado e direcionado para /admin/login.

4.1 Dashboard & Inteligência de Métricas

Acessado em /admin/dashboard, exibe:

  • Contadores Rápidos: Total de cliques em produtos, total de pedidos registrados, produtos ativos e categorias cadastradas.
  • Gráfico de Popularidade (Chart.js): Gráfico de barras alimentado em tempo real com a contagem de cliques recebidos por cada item do cardápio, permitindo ao lojista identificar com clareza quais são os produtos mais desejados pelos clientes.
  • Tabela de Pedidos Recentes: Histórico com ID do pedido, nome do cliente, telefone, endereço, valor total e forma de pagamento.

4.2 Gestão de Categorias (`/admin/categories`)

Permite organizar as seções visíveis do cardápio:

  • Nova Categoria: Botão no topo abre um modal para preenchimento de Nome, Descrição, Ordem de Exibição (número para ordenar na tela) e status (Ativa/Inativa).
  • Edição e Exclusão: Controle simples com feedback visual.

4.3 Gestão de Produtos & Adicionais (`/admin/products`)

Controle completo do catálogo:

  • Cadastro de Produto: Permite definir categoria vinculada, nome, descrição, preço base em Reais e URL de imagem de alta qualidade.
  • Adicionais Dinâmicos: No próprio formulário de cadastro, o lojista pode clicar em "+ Adicionar Opção" e cadastrar complementos com seus respectivos valores (ex: Granulado Extra - R$ 2,50).
  • Ativação/Desativação Rápida: Se um ingrediente estiver em falta, o lojista pode desativar o produto sem precisar excluí-lo do banco.

4.4 Configurações White-Label da Loja (`/admin/settings`)

Tela central para customização da marca:

  • Nome da Loja: Altera o título exibido no cabeçalho e na mensagem do WhatsApp.
  • Segmento / Nicho: Define o subtítulo e ramo de atividade.
  • WhatsApp Oficial: Número de destino de todos os pedidos finalizados.
  • Horários de Abertura e Fechamento: Determina o período em que o botão de checkout ficará liberado.
  • Cor Primária da Marca: Seletor visual de cor (Color Picker). Ao escolher uma nova cor (ex: laranja para frango frito, rosa para cupcakes, vinho para pizzaria), todos os botões, badges e detalhes visuais adotam o novo tom imediatamente.
Manual de Uso do Sistema 5. Produção (VPS) & FAQ

5. Implantação em Produção (VPS Hostinger)

Para publicar o sistema na Hostinger VPS utilizando banco de dados MySQL ou MariaDB:

1
1. Envio dos Arquivos

Clone o repositório GIT na VPS ou envie os arquivos da aplicação para a pasta pública do seu servidor web (ex: /var/www/sualoja/ ou public_html).

2
2. Criação do Banco MySQL

Pelo painel da VPS ou via terminal MySQL, crie uma base de dados vazia (ex: db_pedidos) e um usuário com permissões completas.

3
3. Ajuste do Arquivo `.env`

Copie ou edite o arquivo .env na raiz do projeto configurando as credenciais de produção:

CI_ENVIRONMENT = production
app.baseURL = 'https://sualoja.com.br/'

database.default.DBDriver = MySQLi
database.default.hostname = localhost
database.default.database = db_pedidos
database.default.username = usuario_banco
database.default.password = SenhaSegura123!
database.default.port = 3306
4
4. Execução das Migrações

No terminal da VPS, execute o comando do CodeIgniter:

php spark migrate

Todas as 7 tabelas serão criadas de forma 100% idêntica ao SQLite local!

6. Perguntas Frequentes & Solução de Dúvidas

P: Por que o cliente não consegue clicar no botão de finalizar pedido?

R: Verifique o horário de funcionamento em /admin/settings. Se a hora atual estiver fora do intervalo definido (ex: das 09:00 às 22:00), o sistema bloqueia o checkout por segurança. Para testes 24h, configure o horário das 00:00 às 23:59.

P: Os pedidos são cobrados online dentro do sistema?

R: O modelo do sistema é voltado para agilidade e conversão direta via WhatsApp, minimizando taxas de intermediários. O cliente seleciona se pagará via PIX, Cartão ou Dinheiro, e a confirmação do pagamento é combinada diretamente pelo WhatsApp da loja.

P: Como rodar a suíte de testes automatizados?

R: Basta abrir o terminal na raiz do projeto e executar o comando composer test. Todos os testes unitários do PHPUnit serão executados, validando a integridade das regras de negócio.
